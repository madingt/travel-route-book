# 旅游攻略路书（Travel Route Book）

方法来源：少数派 胡九思《别再把攻略全甩给 AI》（sspai.com/post/114945），并吸收了多次真实行程规划中踩过的坑。
核心立场：**不要一句话生成流水账**。人定方向与取舍，Agent 干体力活（查资料、核地址、算距离、理冲突、排版、把地点落进手机地图）。路书是**活文档**：同一个链接一轮轮迭代，每轮改动都写清楚。

## 四条原则（每一步都过一遍）
1. **从噪音里识别信号**：只有能直接支撑决定（住哪、几点抢票、这家去不去）的信息才进行程。
2. **一手信息优于二手转述**：时间、门票、预约、放号、闭馆、营业时间，回到官网/官方小程序/公众号/地图 App 核对。核对不到就标「待核实」，绝不凭记忆写。
3. **信任具体的人，胜过信任算法**：评论区里带错字、口语化的真实碎碎念 > 精修爆款笔记。
4. **输入质量决定输出质量**：先收齐底稿、官方原文、评论细节、地图数据，再融合。

## 第 0 步：收集信息（一次问完）
出发地与**到达方式（机场/车站名）**、到达与返程的具体时间、日期与天数、同行人与作息、主题、必去/必避、住宿偏好（是否分段住）、体力节奏、口味偏好（如只喝某类咖啡、忌口）。
- 已在上下文或记忆里的不再问；用户不在场时取最合理假设，写在路书顶部「行程假设」。
- **核心事件（演出、开放日、会议）的确切时间地点要尽早拿到**：它决定整天骨架和住在哪。拿不到就做「上午版/下午版」两套，拿到后立刻收敛。
- 用户的作息约束（「前一天还在上班」「上午落地」）要落到第一天的强度上：到达日只排步行和吃喝，不排要预约或赶点的项目。

## 第 1 步：定目标与骨架
- 出行类型：打卡式 / 度假式 / 主题式。主题决定去哪、舍弃什么。
- 先出**骨架**：每天住哪、核心动线、交通方式与大致时长。
- 住宿可以分段：离核心事件近的那晚住过去，其余住交通枢纽。分段住要同步处理**行李**：到达日没酒店放包 → 查寄存点；换住处那天 → 先放行李再出门。
- 用工作日/周末错峰：热门湖景/寺庙放工作日清晨，周末去城市外围。

## 第 2 步：挑景点（做减法）
- 候选来源交叉比对：Agent 列候选 + 小红书真实笔记。
- 舍弃偏离主线、绕路、高峰期体验打折的点；每个舍弃写一句理由放附录。
- 主题偏好要贯彻到底（如喜欢建筑 → 列出建筑师作品；喜欢徒步 → 给具体路线、距离、爬升、退出点）。

## 第 3 步：一手信息核对 + 抢票日历
- 每个需要预约的点核对：渠道（小程序/公众号名）、提前几天、几点放号、是否接受当天预约、闭馆日、最晚入场、开放对象（如部分校园只在周末对公众开放）。
- 规则发布年份要看清，旧规则标「待核实」。
- 生成**抢票日历**放路书顶部：哪天几点、在哪个平台、约什么，带勾选框。日期改了要整体重算放票日。

## 第 4 步：小红书筛选（怎么搜、怎么读、怎么判营销）

### 搜索词
- 用「城市/片区 + 品类 + 真实性词」：`<城市>本地人 <菜系> 不踩雷`、`求本地人推荐 不要广`、`XX 避雷`、`XX 预制菜`、`XX 手冲 小众`。
- **反查每家候选**：`店名 + 避雷 / 预制菜 / 难吃 / 排队`。只搜好评等于只看广告。
- 求助帖（「求本地人推荐」）的**评论区**是金矿：IP 属地为本地的回复优先。

### 读法
- 正文只看信息，结论看评论区：作者回复、反驳、补充、「我去了，确实/一般」。
- 同一家店出现在多个**互不相关**的普通用户笔记里 = 信号；只出现在一个博主或一组相似笔记里 = 噪音。
- 记录时写清「谁说的、在哪说的」，路书附录列出笔记标题与作者，方便用户回查。

### 营销/广告识别清单（命中 2 条以上按营销处理）
- 图片精修、统一滤镜，文案工整、像点评模板（「🌳环境篇🍚美食篇🚗交通篇」）。
- 统一带店铺 tag/定位卡，结尾「快去打卡」「闭眼冲」「天花板」「封神」类口号。
- 账号就是店铺或代运营，或主页全是探店、每篇都是不同城市的「本地人私藏」。
- 只有优点没有缺点；没有价格、没有具体菜名/豆子/处理法这种只有吃过才知道的细节。
- 评论区清一色「求地址」「已收藏」，没有人反驳或补充真实体验；或作者不回复质疑。
- 「排行榜」类笔记先看排序依据：按笔记篇数排的只是热度，只能扩候选，不能当结论。

### 真实信号
- 有具体缺点（「红烧肉老抽放多了」「石锅豆腐中心是凉的」），有价格、人数、点了什么。
- 评论区出现分歧和对话；作者承认「我的确不推荐，点评委婉了」。
- 差评处理：忽略纯口味与偶发服务；多条提到**预制菜/卫生/冷菜回锅**直接划掉；「排队久」看时间是否充裕。

## 第 5 步：地图核实与标注

### 地图选择规则
- **中国大陆境内一律用高德地图**（谷歌在大陆网络下通常加载不出来，对话里的谷歌地图卡片也可能不显示）。
- **中国大陆以外用谷歌地图**（places_search + places_map_display_v0）。

### 高德网页版：查地址与营业时间（在内置浏览器里）
1. 需要登录时打开 amap.com，点头像 → 登录，**让用户自己登录**（扫码或短信），Agent 不输入手机号、验证码、不替用户勾选条款。确认浏览器面板可见，隐藏时先请用户调出来。
2. 搜索 URL：`https://www.amap.com/ssr/search?query_type=TQUERY&query=<URL编码的「城市 + 店名/路名」>&city=<adcode>`。**city 参数常被忽略、按 IP 定位**，query 里必须带城市名；有路名更准。
3. 更稳的取 id 方式：`https://ditu.amap.com/service/poiInfo?query_type=TQUERY&pagesize=3&city=<adcode>&keywords=<关键词>`，返回 poi_list（id、name、address、经纬度）。
4. 详情页 `https://www.amap.com/ssr/search/poi_detail?id=<id>&source=search_result` 读：评分、人均、**营业时间（含每周分段和临时闭店）**、电话、门牌、最近地铁口。用 JS 读 `document.body.innerText` 比截图快。
5. 坐标：`fetch('https://amap-pc-ssr.amap.com/ssr/api/getPoiInfo?id=<id>',{credentials:'include'})` 取 `geo.longitude/latitude`（GCJ-02）。只读，不改账号任何东西。
6. 搜不到的店要当成信号：可能已关店，路书里写明并移出。
7. **营业时间逐条对照行程时段**：每个吃喝点都检查「到店时间是否在营业时段内」（常见坑：店铺只在下午营业，正好与核心活动时段重叠；老字号有午休），冲突就换店或换时间，替代店同样核对。
8. 顺手发现「两个候选其实挨着」就合并成一段。
9. 网页版收藏只有**一个平铺列表、不能建收藏夹**；只能「⋮ → 备注」给每条加前缀（如「<行程名> D2-3 …」）。备注会替换显示名、被编辑的条目会跳到顶部、列表约 20 条懒加载。要建收藏夹/分天路线，走下面的 **iPhone 镜像 + 高德 App**。

### 坐标系
- 高德用 GCJ-02。谷歌 Places 在大陆返回的坐标也是 GCJ-02（实测同一家店差 10–20 米），可直接用于高德标点；境外坐标是 WGS-84。

### 高德标注（多点地图链接，给路书用）
- 链接格式：`https://uri.amap.com/marker?markers=lng,lat,名称|lng,lat,名称|...&src=<任意来源名>&callnative=1`（名称 URL 编码；callnative=1 让手机直接拉起高德 App）。
- **一条链接最多显示 10 个点**，超出被截断 → 按天各做一条，按游览顺序排列。
- 生成后在浏览器里打开一条，确认点数和位置正确。

### 谷歌（境外）
- places_search 拿 place_id 和坐标 → places_map_display_v0 按天出地图，紧接着再写说明文字。

## 第 5.5 步：用 iPhone 镜像把行程落进高德 App（推荐）

### 为什么用 App
- 手机上的高德**已经登录**，不用让用户再扫码，也不碰账号密码。
- App 功能比网页全：**收藏夹**、**路线（带分组、排序、按顺序连线、可直接导航）**、照片识别加点等；网页版做不到。
- 用户出门直接在手机上看「收藏 → 路线 → 我创建的 → <行程名>」，每天一组，点哪个导航哪个。

### 开工前（一次说清，省掉后面大量折腾）
- 请用户在高德 App 里**关闭「截屏后触发分享」**（设置里）。否则 Agent 每截一次镜像画面，iPhone 都当成截屏，高德弹出「截图分享」面板，层层叠加、挡住操作。若已发生，提醒用户检查相册里有无多余截图（不要替用户动相册）。
- iPhone 需锁屏、在 Mac 附近；镜像窗口显示「iPhone 使用中」时请用户锁屏；显示「解锁 iPhone」时点「连接」，需要时请用户在 Mac 上完成验证。
- Mac 上 App 名是中文「**iPhone镜像**」（bundle id `com.apple.ScreenContinuity`），resolve 英文名会找不到。
- computer-use 授权闲置 30 分钟会过期，需要重新 resolve + request access。

### 操作要点（实测）
- **回主屏/找 App**：用菜单「显示 → 主屏幕 / App切换器 / 聚焦」，聚焦里输入「高德地图」再点图标。别靠手势。
- **输入文字用 app_type（后台模式）**：可直接输入中文；全屏模式的 type 会被 Mac 输入法吞成拼音乱码。空格可能丢失，组名/备注用「·」「+」代替空格。
- **滚动基本不可用**（滚轮、拖拽都常失效）。绕开滚动：
  - 加地点用「搜索」而不是在长列表里找；
  - 从收藏夹批量勾选时只勾当前屏可见的；
  - 分组管理左侧栏点组名可直接跳到该组；
  - 把条目「跨组移动」出第 1 组，第 1 组变短，后面的条目自然露出来。
- 「无法从 Mac 使用 iPhone 麦克风」弹窗：点「好」即可，常在切页时出现。
- 全屏模式和 app_* 后台模式坐标系不同：镜像窗口在屏幕上的位置要从全屏截图换算；尽量全程用 app_* 工具，只在后台点不动时才申请全屏控制。
- 截图要省：每次截图后先确认画面稳定再点；关闭弹窗、点按钮、再截图放在同一个 batch 里。

### 高德 App：建分天路线（最佳交付形态）
1. 我的 → 收藏 → 顶部「路线」→「我创建的」→「创建路线」→ 填标题（如「<城市>旅行」），**保持「私密」**（公开需用户明确同意）→ 完成。这条路线同时出现在「我创建的收藏夹」里，所以也满足「建一个收藏夹」的需求。
2. 「添加地点」三种来源：
   - **收藏夹**：多选勾选，**添加顺序 = 勾选顺序**（不是列表顺序），按 D1-1、D1-2… 依次勾。
   - **搜索**：输入「店名 + 路名/片区」，核对地址后点右侧☆；☆变实心并提示「收藏成功」才算加上。**加完等一两秒再清空搜索框**，太快清空会丢（实战 11 个丢了 6 个）。
   - 地图选点 / 照片加点：照片加点和「导入规划」会打开**用户相册**，未经用户同意不要用。
3. 加完回路线页看「N 个地点」核对总数；搜索结果里的☆状态**不可靠**，不能用来判断是否已在路线里。
4. 「排序分组」→「分组管理」→「添加组」建到 Dn；点组名旁✎改名（≤18 字），如「D2·周六·<片区>+<活动>」。
5. 「跨组移动」：勾选条目 → 右下角移动按钮 → 选目标组。**新加的地点会进入当前所在的组**，加完要移到正确的天。勾选框的位置在进入移动模式后会变化，先截图再点，点完放大核对勾的是不是对的。
6. 组内顺序用右侧拖柄调整；最后逐组核对：每组地点、顺序、总数与路书一致。
7. 退出时确认路线页显示的起终点与总数；交付时告诉用户入口路径。

### 高德 App 收藏夹（只需要收藏不需要路线时）
- 收藏 → 地点 →「创建收藏夹」；或在地点详情「⋮ → 将地点添加到」勾选目标收藏夹。取消勾选即从该收藏夹移出。
- 误加的地点：路线详情里该条「⋮ → 将地点添加到」取消勾选当前路线即可移除（不影响默认收藏夹）。

## 第 6 步：餐饮/咖啡匹配
- 每天 1–2 家核心正餐贴合动线，其余放「随缘备选」。
- 口味过滤贯彻到底（如只喝黑咖啡 → 排除以特调/奶咖出名、手冲被吐槽的店，表格里划掉并写原因）。
- 每家写：门牌、最近地铁口、营业时间、为什么留下（引用真实评论）。

## 第 7 步：反向审查（必做）
以专业导游视角质询：体力透支、同日跨区折返、闭馆日（多数博物馆周一闭馆）、营业时间冲突、预约放号日、行李怎么处理、到达日强度、返程缓冲（起飞前 3 小时从市区出发）、雨天怎么办。列出问题与改法写进附录。

## 第 8 步：天气与临近复核
- 出发前约一周的预报才可信：用 send_later（回到同一会话，保留上下文）在**出发前 2 天上午**安排一次复核：查中央气象台 nmc.cn + 另一来源交叉；按天气逐日调整户外段；在总览顶部加醒目的「天气调整」区块，被调整的条目加「已调整」标记；SendUserMessage 发总结 + 需要用户立刻动手的事。
- 定时提示词要自带全部上下文：路书 URL、本地文件路径（容器可能被回收，回收后先用 Artifact read 取回）、日期、住宿、核心事件、调整规则。
- 行程调整后，同步更新手机里的高德路线（增删地点、跨组移动）。

## 输出

### HTML 路书（Artifact，同一 URL 迭代）
1. 顶部：行程假设、日期条。
2. 选项卡：总览 / 抢票日历 / D1…Dn / 地图 / 地址簿 / 咖啡或兴趣清单 / 吃 / 附录。
3. 总览：每天一张卡（主题、核心点、住处），点击进入当日；天气提示。
4. 每日页：时间轴（时间 + 地点门牌 + 营业时间 + 交通方式与时长）、「在高德/谷歌地图看今天的地点」按钮、雨天方案、随缘备选、页底「← 上一天 / 下一天 →」。
5. 地图页：每天一张多点地图链接 + 编号地点列表 + 「手机高德：收藏 → 路线 → 我创建的 → <行程名>」入口说明。
6. 地址簿：天 / 地点 / 门牌·营业时间·电话·地图链接 / 状态（地图核实、只到片区、未定位、已移出）。
7. 附录：反向审查、舍弃清单、待核实清单、一手信息来源、小红书笔记标题与作者、本轮改动记录。

### 交互实现（实战踩坑后的硬性要求）
- **站内跳转不要用 `<a href="#xx">`**：Artifact 外层会拦截 # 链接。脚本启动时把站内 # 链接改成按钮（移除 href、加 data-go、role=button、tabindex=0），用捕获阶段的 click/keydown 监听切换分页。
- CSS 必须写 `[hidden]{display:none!important}`，否则离线文件里所有分页叠在一起。
- **无脚本兜底**：分页默认全部显示，由脚本隐藏非当前页。
- 勾选框状态存 localStorage（try/catch 包住），改日期后换存储键。
- 外部地图链接 `target="_blank"`，不要转成按钮。
- 每次发布前用 Playwright 本地跑一遍：切标签、点每日卡片、上一天/下一天、模拟外层拦截 a[href]、禁用 JS 时分页全可见、390px 宽无横向溢出。
- 发布到同一个 Artifact URL；同时用 SendUserFile 发离线 .html（景区信号差时用）。

### 地点清单表（用户要表格时）
- 一行一个地点：天 / 日期 / 星期 / 高德分组名 / 组内序号 / 总序号 / 地点 / 类型 / 安排备注 / 地址 / 高德 POI ID / 高德链接（HYPERLINK 拼 poi_detail URL）。
- 另一页按天、按类型用 COUNTIF/COUNTIFS 统计，合计用 SUM；按天着色、冻结表头、加筛选。

### 迭代方式
- 用户每补充一个事实（到达时间、机场、住哪、事件时间），立刻改骨架 → 联动改抢票日历、地址簿、地图链接、手机高德路线、反向审查。
- 每轮回复：一句话说改了什么 + 列关键调整 + 还需要用户做的事。不复述整份行程。

## 不要做
- 凭记忆写门票、开放时间、放号规则、营业时间。
- 把营销笔记的店当推荐；把一篇笔记或热度榜当结论。
- 只给「区域」不给门牌；给了店却没核对营业时间和行程时段是否冲突。
- 在大陆用谷歌地图，或把超过 10 个点塞进一条高德链接。
- 替用户登录、输入验证码、勾选协议、抢票或下单。
- 未经同意打开用户相册（照片加点/导入规划）、把路线设为公开、删除用户已有的收藏。
- 没关「截屏后触发分享」就开始大量截图；搜索加点后立刻清空导致丢点却不核对总数。
- 从早排到晚、到达日排重活、同日跨区来回折返。
