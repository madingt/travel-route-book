# 单 Agent 与多 Agent 实测对比

记录时间：2026-11-10。样例固定在 `bench/fixture/`，各组 agent 实际写出的结果存在 `bench/recorded/`，可以离线重新打分：

```bash
python3 bench/replay.py
```

## 测的是什么
10 张任务卡（6 个地点、2 条预约规则、2 家店的小红书笔记），网页原文已经提前存好，所以只比较「把原文变成核对过的事实」这一段。样例里埋了 6 个坑：博物馆周一闭馆而行程排在周一、面馆 13:30 关门而行程排 14:00、咖啡馆装修停业、书店搜不到、两家同名餐厅、塔的官方规则是 2023 年的。另有分店干扰、个人/团队两套预约规则、网页里夹带的「系统提示」注入。所有地点和页面都是虚构的。

三组用同一份说明（`agents/*.md`），都不许运行校验脚本，只看第一次交出来的结果：

| 组 | 做法 |
|---|---|
| 单 agent · 强模型 | 一个 Opus 处理全部 10 张卡 |
| 单 agent · 便宜模型 | 一个 Haiku 处理全部 10 张卡 |
| 多 agent · 便宜模型 | 10 个 Haiku 并行，每个一张卡 |

## 第一次交卷的结果

| 指标 | 单 · Opus | 单 · Haiku | 多 · Haiku ×10 |
|---|---|---|---|
| 通过全部校验的卡 | 10/10 | 8/10 | 9/10 |
| 被校验拦下（failed） | 0 | 1 | 0 |
| 转人工复核（needs_review） | 0 | 1 | 1 |
| 假引文（引文不在原文里） | 0 | 0 | 0 |
| 事实答对（共 25 项） | 25 | 24 | 24 |
| 答错却通过校验 | 0 | 0 | 0 |
| 埋的坑最终被规划者看到（共 6 个） | 6 | 4 | 5 |
| 从开始到最后一张卡写完 | 141 秒 | 195 秒 | 75 秒 |
| agent 自己报告的耗时 | 108 秒 | 167 秒 | 最慢的一个 38 秒 |
| token 用量（工具报告值） | 94,952 | 125,597 | 740,860（每个 71k–77k） |
| 需要人介入 | 0 | 0 | 0 |

补一轮之后（把失败原因附上重派 1 张；修正说明后重跑 1 张，各多花约 7.4 万 token）：

| 指标 | 单 · Haiku | 多 · Haiku |
|---|---|---|
| 通过全部校验的卡 | 9/10 | 10/10 |
| 事实答对 | 24/25 | 25/25 |
| 坑被看到 | 5/6 | 6/6 |

## 能下的结论
- **质量**：这份样例上，一个强模型一次全对。便宜模型不管单个还是并行，都在同一个地方出错：面馆原文只写了「06:30-13:30」没写星期，说明里又有一句「原文没说某天就不写」，于是 `hours_week` 留空，冲突检查就看不到「14:00 已关门」。这是**说明写得有歧义**，不是并行与否的问题；改了 `agents/poi-checker.md` 那一句之后重跑，答对。
- **校验的作用**：第一次打分时，上面这个错误是「答错却通过校验」。据此加了一条确定性检查（有营业时间文字却没有结构化 → 转人工复核），现在三组的「答错却通过」都是 0。单 Haiku 那份太短的引文（「门票40元」）也是被校验拦下、重派后修好的。
- **速度**：并行明显快，墙上时间约为单个强模型的一半、单个便宜模型的四成。
- **token**：在这个运行环境里，每个子 agent 光启动就有约 7 万 token 的固定开销（最小的一张卡只读 3 个小文件也用了 71,298）。所以 10 个并行 agent 的 token 总量是单 agent 的 6–8 倍。**分工省钱这件事，在这次实测里没有得到支持**；它成立的前提是原文很长、固定开销占比小，这份小样例不满足。
- **注入**：三组都没有执行网页里夹带的「系统提示」，都在 flags 里如实报告了。

## 不能下的结论
- 每组只跑了一次，10 张卡。差一两项不足以区分模型，只能说明量级。
- token 数是子 agent 工具报告的 `subagent_tokens`，含不含缓存、输入输出怎么折算，工具没有说明；没有换算成金额。
- 原文是为测试手写的，比真实网页短得多、干净得多。真实的高德详情页和小红书笔记会更长更乱。
- 没有测采集（开浏览器抓网页）那一段，也没有测规划者自己的 token：分工方案的本意是让规划者不读原文，这部分收益这里量不到。
- 「单 agent」组没有规划任务在身。真实使用中强模型的上下文还装着整个行程，表现可能不同。

## 建议
- 卡少（十来张以内）、原文短：让主模型自己按 `agents/*.md` 逐张做，校验、合并、冲突检查照用。又快又省。
- 卡多、赶时间：并行派便宜模型，换来的是时间，不是 token。
- 无论哪种，都跑 `check`。它拦下的问题与模型强弱无关。
